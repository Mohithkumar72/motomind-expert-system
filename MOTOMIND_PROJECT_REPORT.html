ABSTRACT

MotoMind is a full-stack, rule-based Artificial Intelligence (AI) expert system engineered to diagnose and troubleshoot mechanical, electrical, fuel, and engine anomalies in two-wheelers (motorcycles and scooters). Modern two-wheeler riders and field service technicians frequently encounter unexpected breakdown symptoms—such as starter click without cranking, sluggish throttle acceleration, abnormal engine clatter, overheating, or rapid battery drain—yet lack immediate access to diagnostic expertise. MotoMind bridges this gap by emulating human specialist troubleshooting through a formal Knowledge Base, Working Memory, and Forward-Chaining Inference Engine.

The platform combines an interactive, automotive-styled React.js frontend dashboard with a high-performance Python REST API backend. The system organizes two-wheeler diagnostic knowledge across four fundamental vehicle subsystems: Starting Problems, Engine Problems, Performance Problems, and Electrical Problems, comprising 12 canonical observable symptoms. Domain knowledge is encoded as 12 production rules utilizing propositional logic (IF-THEN clauses), incorporating prerequisite activation thresholds, fault categories, and severity tiers (Low, Medium, and High).

The inference engine implements forward-chaining pattern matching against user-reported symptoms. It deterministically calculates a percentage-based confidence score based on the intersection between observed facts and rule preconditions. Diagnosed faults are prioritized through a multi-tier ranking heuristic (Match Percentage → Matched Count → Severity Weight). For each deduced fault, MotoMind renders transparent justifications displaying the exact rule condition triggered, mechanical root cause explanations, ordered step-by-step troubleshooting procedures, and certified mechanic advisories.

Extensive validation demonstrates 100% deterministic accuracy across single-fault and multi-fault scenarios, successfully isolating complex conditions such as battery depletion versus starter relay failure, ignition misfires versus carburetor clogging, and stator charging degradation versus chassis ground short circuits. Unlike opaque statistical machine learning models, MotoMind delivers verifiable, explainable, and zero-hallucination diagnostics, serving as an effective educational tool and preliminary diagnostic guide.

1. AIM AND OBJECTIVES

To design and develop MotoMind, a full-stack web-based Artificial Intelligence Expert System that assists riders and technicians in identifying common motorcycle and scooter faults by analyzing reported symptoms through a Python-powered rule-based inference engine and an interactive React.js diagnostic dashboard.

The primary objectives of this project include:

  • To formalize two-wheeler mechanical and electrical troubleshooting knowledge into a structured Knowledge Base of declarative production rules (IF-THEN).
  • To implement a deterministic forward-chaining inference engine in Python that evaluates symptom combinations without relying on external cloud AI APIs or black-box neural networks.
  • To calculate mathematical confidence scores (match percentages) and rank multiple potential faults by likelihood and severity.
  • To build a responsive automotive dashboard in React.js featuring dynamic category filtering, demo presets, real-time counters, and print-ready report generation.
  • To provide complete diagnostic explainability, giving the rider concrete reasons why a fault was deduced along with actionable troubleshooting instructions.

Unlike procedural code where logic is tightly coupled with control flow, MotoMind isolates Domain Knowledge from the Inference Mechanism. This enables automotive specialists to update mechanical rules without altering core execution code. Furthermore, unlike machine learning which requires vast statistical training sets and produces opaque probabilities, MotoMind's rule-based reasoning offers 100% auditability and safety.

2.4 Production Rules & Forward-Chaining Inference Mechanism

The inference engine operates on forward chaining: taking input facts from working memory and comparing them against the precondition antecedent vector of each production rule. When a rule satisfies its minimum threshold criterion ($k \ge \text{min\_required}$), the rule fires and generates a candidate fault.

Match Confidence (%) = ( Number of Matched Rule Symptoms / Total Symptoms Defined in Rule ) × 100%

Candidate diagnoses are then prioritized by a deterministic 3-tuple sorting key:

  1. Match Percentage (Descending): Highest proportional symptom convergence.
  2. Matched Symptom Count (Descending): Resolves ties in favor of higher absolute evidence.
  3. Severity Weight (Descending): High (Weight = 3) > Medium (Weight = 2) > Low (Weight = 1).

3.1 Python Rule-Based Inference Engine
Repository file: motomind-react-python/backend/engine.py
class RuleBasedInferenceEngine: SEVERITY_WEIGHT = {"High": 3, "Medium": 2, "Low": 1} def __init__(self, rules=None): self.rules = rules if rules is not None else EXPERT_RULES def diagnose(self, selected_symptom_ids: List[str]) -> Dict[str, Any]: selected_set = set(selected_symptom_ids) diagnosed_faults = [] for rule in self.rules: matched_ids = [s for s in rule["symptoms"] if s in selected_set] match_count = len(matched_ids) # Check rule activation threshold if match_count >= rule.get("min_required", 1): match_percentage = round((match_count / len(rule["symptoms"])) * 100) matched_labels = [SYMPTOM_LOOKUP.get(s, {}).get("label", s) for s in matched_ids] missing_labels = [SYMPTOM_LOOKUP.get(s, {}).get("label", s) for s in rule["symptoms"] if s not in selected_set] diagnosed_faults.append({ "rule_id": rule["id"], "fault": rule["fault"], "category": rule["category"], "severity": rule["severity"], "match_percentage": match_percentage, "match_count": match_count, "total_symptoms": len(rule["symptoms"]), "matched_symptoms": matched_labels, "missing_symptoms": missing_labels, "rule_condition": rule["rule_condition"], "explanation": rule["explanation"], "troubleshooting": rule["troubleshooting"], "mechanic_advice": rule["mechanic_advice"] }) # Multi-factor priority ranking: Match % -> Match Count -> Severity Weight diagnosed_faults.sort( key=lambda x: (x["match_percentage"], x["match_count"], self.SEVERITY_WEIGHT.get(x["severity"], 0)), reverse=True ) return {"status": "success", "results": diagnosed_faults}

4.3 Diagnostic Dashboard Layout & Card Presentation

When the user triggers diagnosis, MotoMind renders diagnostic cards featuring:

  • Likelihood Rank & Category: Displays ordinal ranking (e.g. #1 Likely Cause) and component subsystem (e.g. Electrical & Starting).
  • Confidence Meter & Severity Tag: Visual animated progress bar reflecting the calculated match percentage alongside color-coded severity badges (Red for High, Amber for Medium, Green for Low).
  • Transparent Logic Banner: Discloses the triggered knowledge base rule (e.g. IF ('Bike won't start' OR 'Clicking sound') AND ('Headlight not working')).
  • Expert Explanation: Clear technical description detailing mechanical friction, voltage drops, or stoichiometric ratio disruption.
  • Numbered Troubleshooting Checklist: Sequenced action steps starting from simple non-invasive inspection to multimeter testing.
  • Professional Safety Guidance: Highlights critical mechanical hazards requiring workshop intervention before riding.

5. CONCLUSION

MotoMind successfully demonstrates the practical implementation of an Artificial Intelligence Rule-Based Expert System for two-wheeler fault diagnosis. By separating domain knowledge into declarative production rules in Python and providing a real-time reactive user interface in React.js, the system delivers instantaneous, 100% explainable, and deterministic troubleshooting recommendations. Experimental test cases confirm that the forward-chaining pattern matching algorithm accurately identifies critical faults across electrical, starting, engine, and fuel systems while preventing hallucinated diagnoses. Future work includes expanding the rule base to include fuel injection ECU error codes, integrating OBD-II Bluetooth telemetry streaming, and supporting localized multilingual audio diagnosis guides.
